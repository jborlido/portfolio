Autonomous AI Agents for Engineering Ops

A self-hosted multi-agent system where AI agents run daily operations: shipping pull requests, running team standups end-to-end, and handling deep research — while costs stay predictable.

01The Problem

Small teams drown in operational overhead. Standups need running, status needs collecting, routine code changes need making, and research questions pile up — none of it is anyone's "real job," but all of it eats the week. Hiring for it doesn't scale at startup size; ignoring it means things slip.

The question I set out to answer: how much of this can autonomous AI agents actually own — not as demos, but as reliable infrastructure that runs every day?

02The System

The result is a fleet of autonomous AI agents running on self-hosted Linux machines. Each agent is fully isolated — one agent, one service, one control surface — so a misbehaving agent can't take down its siblings.

  • An ops agent runs daily standups end-to-end. It reads the team's updates, opens threads to ask clarifying questions, requests and analyzes screenshots, cross-references the project-management board against actual git activity, and publishes a daily verdict to a reports repository.
  • An engineering agent ships code. It picks up scoped tasks and opens pull requests autonomously — humans review, the agent iterates on feedback.
  • A research agent handles deep-dive investigations — the questions that would otherwise sit in a someday pile.
  • A personal assistant agent manages calendars, tasks, and the glue work between the others.

04Under the Hood

  • Isolation by design: one agent = one isolated service under systemd supervision, each with its own Discord bot as a control surface. Chat is the UI — no custom frontend to maintain.
  • Custom tool belt: purpose-built CLI tools for task management, GitHub, and calendars, so agents act through the same interfaces a human would.
  • Conditional triggers, not cron-spam: agents wake on meaningful conditions rather than fixed schedules, so LLM calls only fire when there's a reason. This is the difference between a predictable bill and a runaway one.
  • Zero-dependency cost dashboard: a lightweight usage monitor tracks what every agent spends, per day, at a glance.
  • Conversation memory: agents keep context across sessions, so Tuesday's agent remembers Monday's decisions.

Design principle: agents earn autonomy incrementally. Each one starts supervised, proves itself on low-stakes work, and graduates to running unattended — with humans always reviewing the output that matters (like pull requests).

05What Came Out of It

  • Standups run daily without a human facilitator — and the cross-referencing against git activity catches drift that a tired human wouldn't.
  • Scoped engineering tasks get turned into reviewable pull requests without a developer context-switching to them.
  • Costs stay flat and predictable through trigger design — the system doesn't burn tokens idling.
  • The architecture generalizes: the same pattern (isolated agents + custom tools + chat control surface) now underpins how I automate operations in the companies I run.
